# Вкладка «Файлы» и отложенный контекст (паттерн из TT3DatoE)

UX-паттерн из мобильного приложения TT3DatoE: вкладка, где пользователь
просматривает документы и файлы репозитория, а затем «отправляет в чат»
содержимое файла как контекстное сообщение. Отправка переживает смену вкладок
через отложенный контекст.

## Механизм

```
┌─ FilesScreen ─────────────┐        ┌─ ChatScreen ─────────────────┐
│ docs (локальные заметки)   │        │ on mount: loadPendingContext() │
│ tree repo (локальный/gh)   │        │ если есть → создать сообщение   │
│ открой файл → view         │        │  "[Файл из репозитория: path]…" │
│  ▼ "Отправить в чат"       │        │  в активный чат (или новый)     │
│  savePendingContext(...)   │        │  clearPendingContext()          │
│  navigate("chat")          │        └────────────────────────────────┘
└────────────────────────────┘
```

## PendingContext (хранилище, localStorage)

```ts
interface PendingContext {
  content: string;   // "[Файл из репозитория: <path>]\n\n<текст файла>"
  title: string;     // путь файла → заголовок нового чата
  ts: number;        // время сохранения
}
```

- **TTL 10 минут**: контекст старше 10 мин игнорируется и удаляется
  (`now() - p.ts > 10 * 60 * 1000`).
- **Ключ**: `tt3datoe.pendingContext.v1`.
- При создании чата заголовок = `pending.title` (путь файла).

## Поведение при получении

На маунте ChatScreen:
1. `loadPendingContext()` — если `null`, ничего не делать.
2. `clearPendingContext()` — контекст одноразовый.
3. Найти активный чат (`loadActiveConv`); если его нет — создать новый
   (id `conv`, title = `pending.title`, model = `auto`).
4. Добавить user-сообщение `{ content: pending.content }`.
5. Сохранить список чатов и сделать новый активным.

## Разделение источников файлов

| Режим | Источник | Плюсы |
|---|---|---|
| `local` | dev-сервер `/__repo/tree`, `/__repo/file?path=` | работает офлайн, это текущий репозиторий на сервере |
| `github` | GitHub API (`fetchRepoTree`/`fetchRepoFile` из `tools/github`) | любой репозиторий, нужен токен для приватных |

Кнопка «Проверить токен» → `verifyGithubToken(token)` → выводит логин.

## Автоконтекст (пассивная версия)

Тот же механизм, но без вкладки: файлы, **упомянутые в тексте сообщения**,
автоматически встраиваются в контекст. См. `core/memory/src/repo-context.ts`
(`buildRepoContext`, `FILE_RE`, максимум 5 файлов). Порядок: локальное дерево
сначала, GitHub — fallback.

## Ключевые решения

- **Один `sendToChat`, никакой прямой передачи между экранами.** Вкладки
  пересоздаются; переход через хранилище с TTL — самый простой надёжный способ.
- **Контент всегда обёрнут в заголовок** `[Файл из репозитория: <path>]` — LLM
  видит происхождение файла.
- **Пустой/недоступный файл тихо пропускается** — вкладка не падает.
- Файлы > 300 КБ и бинарники недоступны для просмотра/отправки
  (`isViewableFile` в `tools/github/github.ts`).
